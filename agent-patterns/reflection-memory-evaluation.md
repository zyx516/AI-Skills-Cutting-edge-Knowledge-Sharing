# Reflection, Memory, and Evaluation

## English

**Reflection** turns feedback from a previous attempt into a concise lesson for the next attempt. It should not mean endlessly asking the model to “try again.” A useful reflection records what failed, why it likely failed, what evidence supports that diagnosis, and what concrete change will be tried next.

**Memory** stores only information that can improve later decisions: task constraints, validated facts, tool results, decisions, and failure lessons. Good memory is selective, scoped, and refreshable; stale or unverified notes can make an agent confidently wrong.

**Evaluation** closes the loop. Before deployment, define representative tasks and success criteria. During operation, collect failure cases, inspect them, and update prompts, tools, policies, or tests. Measure quality, cost, latency, and safety—not just whether the output sounds plausible.

## 中文说明

**反思（Reflection）**是把上一次尝试得到的反馈转化为下一次尝试的简明经验。它不应等同于让模型无限地“再试一次”。有效反思会记录：哪里失败、可能原因、支持这一判断的证据，以及下一步准备做出的具体改变。

**记忆（Memory）**只保存能改善未来决策的信息：任务约束、已验证事实、工具结果、关键决策和失败经验。好的记忆应是有选择的、范围受控的，并且可刷新；过期或未经验证的记录会让 Agent 自信地犯错。

**评测（Evaluation）**让循环真正闭合。在部署前，要定义具有代表性的任务和成功标准；运行中要收集失败案例、检查原因，并更新提示词、工具、策略或测试。应同时衡量质量、成本、延迟和安全性，而不是只看输出是否“听起来合理”。
